# 登记网页混合编码与字段歧义隔离

把“原始 HTTP 响应 → 结构化登记档案”的采集入口补齐：混合编码按证据链判定、
冲突样本隔离、分块流式解码、按页面区块解析字段、人工解隔离后只重放受影响样本。
不针对单个站点写字符串替换，所有行为由来源规则驱动。

## 运行

Python 3.11.10，仅标准库，无需安装依赖、无网络访问：

```sh
python3 -m unittest discover -s tests -v
python3 demo.py
```

`demo.py` 读取仓库内 fixtures 跑完整端到端流程（首遍采集 → 隔离 → 人工解隔离
重放 → 幂等复跑），输出 JSON，重复执行结果完全一致。状态只在内存中，不写仓库。

## 模块

| 模块 | 职责 |
| --- | --- |
| `harvest/stream.py` | 分块接收、增量解码（多字节字符跨块不中途报错）、字符偏移→原始字节偏移映射 |
| `harvest/evidence.py` | BOM / HTTP 头 / 页面 meta / 来源配置 / 人工确认五类编码证据，冲突即隔离 |
| `harvest/blocks.py` | 按区块（`data-section` 等）解析 `labeled_text` 与 `dl` 两种页面，片段带字节位置 |
| `harvest/mapping.py` | 区块内别名映射；保留原 `service.map_record` 接口，同名冲突不取第一个值 |
| `harvest/dates.py` | 日期格式与时区只按来源规则解析，无法确定保留原值并标注，绝不猜测 |
| `harvest/records.py` / `harvest/store.py` | 档案与隔离单结构、内容哈希幂等、JSON 导出 |
| `harvest/pipeline.py` | 编排：流式接收 → 编码判定 → 区块解析 → 档案/隔离 → 定向重放 |
| `fixtures/harvest_rules.json` | 来源 a/b 的编码、区块、别名、日期规则 |

## 关键规则

### 编码判定与隔离

- 证据区分 `bom`、`http`、`meta`、`source`、`manual`，每条带依据类型与字节位置。
- 自动证据互相冲突（如 a：HTTP 头 UTF-8 与页面 meta GB18030），或所有候选都
  无法对完整字节严格无损解码时，样本进入隔离区。禁止用 `errors='replace'`
  吞掉错误后入库；替换解码只生成隔离单里明确标注“不可入库”的人工诊断预览。
- 人工确认仅用于隔离重放，且仍要对完整字节做严格验证；错误的人工编码同样拒绝入库。

### 流式接收

- 增量解码器在 `final=False` 时保留不完整的多字节序列，不把暂时不完整当永久坏页；
  只有整段接收完毕、严格解码仍失败才判定坏页。fixtures 的分块边界有意切在
  GB18030 双字节与 UTF-8 三字节字符内部，`crossed_chunk` / `label_crossed_chunk`
  会标注跨越分块边界的片段。

### 区块与字段

- 同名标签在不同区块（“本次登记 current”/“历史登记 history”）各自独立成档案，
  互不覆盖；同一区块内同名标签多值、或别名解析出不同值，按冲突隔离。
- 每条档案都带来源标识、本地企业编号、区块身份、片段字节位置与解析依据。
  企业身份限定在来源内，不同来源即使编号相同（fixtures/pages 中均为 `7`）也不合并。
- 日期（如 b 的 `01/02/2020`）按来源声明的 `%d/%m/%Y` 解析为 `2020-02-01`；
  无规则可解释的日期保留原值并标记 unresolved，必填日期无法确定则隔离。

### 解隔离与重放

- 隔离单保留 Base64 原始字节、分块边界、全部编码证据与候选验证结果。
- 人工补齐编码或区块规则后，`replay()` 只重放该样本，其他来源继续采集、档案不变。
- 档案 id 由来源、本地企业编号、区块与字段内容哈希决定，重复重放/复跑命中幂等
  键，不会多发一份档案；隔离单标记 resolution 后保留以便审计。

## 测试覆盖

`tests/` 共 48 个用例：流式跨块、BOM/证据冲突、严格无损解码、区块解析与同名标签
冲突、日期规则、端到端隔离与解隔离（含错误人工编码拒绝、重放幂等）、跨来源不
合并；同时通过 `load_tests` 加载根目录原有 `test_service.py` 回归。

## 合成材料

`fixtures/responses.json` 用 Base64 保存原始响应，`chunks` 为累计字节边界；
`fixtures/pages/` 保留可读页面；`fixtures/rules.json` 为历史别名映射示例，
`fixtures/harvest_rules.json` 为采集来源规则。仅使用仓库内材料。
